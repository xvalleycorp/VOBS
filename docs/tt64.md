# Đối chiếu Thông tư 64/2024/TT-NHNN

Thông tư 64/2024/TT-NHNN ngày 31/12/2024 quy định triển khai Open API trong ngành ngân hàng, có hiệu lực từ
01/03/2025. Ngân hàng đã kết nối với bên thứ ba phải tuân thủ đầy đủ **trước 01/03/2027** (Điều 15).

Trang này đối chiếu phần thân Thông tư với VOBS. **Phụ lục 01** (đặc tả kỹ thuật từng API) và **Phụ lục 02** (tiêu
chuẩn kiến trúc, dữ liệu, an toàn thông tin) chưa được đối chiếu vì chưa lấy được toàn văn từ nguồn mở; đó là việc
cần làm tiếp theo (xem cuối trang).

## Danh mục Open API cơ bản (Điều 6 khoản 1)

Mỗi API tương ứng một operation trong [`vobs-spec/openapi/vobs-open-api.yaml`](../vobs-spec/openapi/vobs-open-api.yaml),
đánh dấu bằng `x-tt64.ref`. CI chạy [`check_tt64_coverage.py`](../vobs-spec/scripts/check_tt64_coverage.py) để bảo đảm
đủ danh mục trong [`tt64-catalog.json`](../vobs-spec/tt64-catalog.json).

| Mã | API trong Thông tư | VOBS |
| --- | --- | --- |
| 6.1.a.1 | API Lấy thông tin lãi suất | `GET /interest-rates` |
| 6.1.a.2 | API Lấy thông tin tỷ giá | `GET /exchange-rates` |
| 6.1.b.1 | API Xác nhận và lấy sự đồng ý của khách hàng | `POST /consents` |
| 6.1.b.2 | API Lấy mã truy cập | `POST /oauth2/token` (`authorization_code`) |
| 6.1.b.3 | API Làm mới mã truy cập | `POST /oauth2/token` (`refresh_token`) |
| 6.1.b.4 | API Thu hồi mã truy cập | `POST /oauth2/revoke` |
| 6.1.b.5 | API Lấy danh sách tài khoản | `GET /accounts` |
| 6.1.b.6 | API Lấy thông tin tài khoản | `GET /accounts/{accountId}` (kèm số dư) |
| 6.1.b.7 | API Lấy lịch sử giao dịch | `GET /accounts/{accountId}/transactions` |
| 6.1.c.i.1 | API Khởi tạo thanh toán | `POST /payments` |
| 6.1.c.i.2 | API Xác nhận khách hàng Luồng Redirect | `GET /oauth2/authorize` |
| 6.1.c.i.3 | API Lấy mã truy cập Luồng Redirect | `POST /oauth2/token` (`authorization_code`) |
| 6.1.c.i.4 | Cập nhật trạng thái xác thực thanh toán, luồng Decoupled* | webhook `paymentAuthenticationUpdated` |
| 6.1.c.i.5 | Xác nhận thanh toán* | `POST /payments/{paymentId}/confirmation` |
| 6.1.c.i.6 | Lấy trạng thái giao dịch* | `GET /payments/{paymentId}` |
| 6.1.c.i.7 | Lấy trạng thái xác thực thanh toán, luồng Decoupled* | `GET /payments/{paymentId}/authentication` |
| 6.1.c.ii.1 | API Nạp ví điện tử | `POST /ewallet-topups` |
| 6.1.c.ii.2 | API Xác nhận OTP | `POST /ewallet-topups/{transferId}/otp` |
| 6.1.c.ii.3 | Cập nhật trạng thái xác thực nạp ví, luồng Decoupled* | webhook `topupAuthenticationUpdated` |
| 6.1.c.ii.4 | Lấy trạng thái xác thực nạp ví, luồng Decoupled* | `GET /ewallet-topups/{transferId}/authentication` |
| 6.1.c.ii.5 | Xác nhận nạp ví điện tử* | `POST /ewallet-topups/{transferId}/confirmation` |
| 6.1.c.ii.6 | Lấy trạng thái giao dịch* | `GET /ewallet-topups/{transferId}` |
| 6.1.c.iii | Open API Rút tiền ra khỏi ví điện tử | `POST /ewallet-withdrawals` (thân Thông tư không liệt kê API con) |

\* Tên tiếng Việt dịch lại từ bản tiếng Anh của LuatVietnam, chưa khớp nguyên văn. Chiều gọi của hai API "cập nhật
trạng thái xác thực" (ngân hàng gọi bên thứ ba qua webhook) là giả định của VOBS.

Open API ngoài danh mục được phép triển khai nhưng phải tuân thủ Phụ lục 02 (Điều 5).

## Quy định khác và cách VOBS đáp ứng

| Quy định | Nội dung | VOBS |
| --- | --- | --- |
| Điều 5 | Nhóm điểm c chỉ cấp cho bên thứ ba là ngân hàng hoặc tổ chức trung gian thanh toán | Quy tắc `PAYMENT_GROUP` trong bảng quyết định `consent_request` của `vobs-consent`; đặc tả trả `403 scope_not_permitted` |
| Điều 8 | Hợp đồng với bên thứ ba: bảo mật, dùng dữ liệu đúng phạm vi, báo sự cố, quyền truy cập dữ liệu | Ngoài phạm vi phần mềm; phạm vi dữ liệu thực thi bằng consent |
| Điều 9 | Công khai thông tin hệ thống thử nghiệm và danh mục Open API trên trang chính thức trước khi kết nối | `vobs-sandbox` (Microcks) dựng từ cùng bộ đặc tả |
| Điều 11 | Công cụ cho khách hàng tra cứu dữ liệu đã đồng ý chia sẻ và rút lại đồng ý | `GET`, `DELETE /consents/{consentId}`; `ConsentService.revokeByCustomer` |
| Điều 11 | Thời hạn truy vấn sau khi đồng ý không quá 180 ngày, trừ khi có thỏa thuận khác | Quy tắc `VALIDITY` trong bảng `consent_request`; `validityDays` tối đa 180. Thỏa thuận khác: ngân hàng thêm phiên bản bảng có ngày hiệu lực |
| Điều 11 | Giới hạn số lần truy vấn tự động | `limit-count` theo bên thứ ba tại gateway; đặc tả trả `429` |
| Điều 11 | Giám sát, phát hiện và ngăn truy cập bất thường | Quan sát qua OpenTelemetry; module Fraud (giai đoạn 3) |
| Điều 11 | Log mọi lần sử dụng Open API, lưu tối thiểu 3 tháng, sao lưu tối thiểu 1 năm | `kafka-logger` vào topic kiểm toán; cấu hình lưu giữ trong `vobs-deploy` |
| Điều 11 | Hệ thống thông tin đạt tối thiểu cấp độ 3 | Gói tuân thủ: ánh xạ kiểm soát theo Nghị định 85/2016 và Thông tư 09/2020 |
| Điều 12 | Bên thứ ba có công cụ trực tuyến cho khách hàng tra cứu và rút lại đồng ý | `GET`, `DELETE /consents/{consentId}` cho bên thứ ba |
| Điều 15 | Nộp danh mục API và kế hoạch trước 01/07/2025; tuân thủ đầy đủ trước 01/03/2027 | Bảng trên dùng được làm khung cho danh mục API của ngân hàng |

## Việc cần làm

- [ ] Lấy toàn văn Phụ lục 01, Phụ lục 02 (Công báo, hoặc tài khoản thuvienphapluat.vn) và đối chiếu đường dẫn, tên
      trường, mã lỗi, yêu cầu xác thực, mã hóa, chữ ký của từng API.
- [ ] Khớp tên tiếng Việt của các API đánh dấu * với nguyên văn.
- [ ] Xác định chiều gọi của các API "cập nhật trạng thái xác thực" trong luồng decoupled.
